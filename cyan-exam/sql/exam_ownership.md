# 考试资源权限迁移说明

## 本轮范围

- 在原有接口动作权限之外，增加考试负责人或内置管理员校验。
- 内置管理员沿用项目现有规则：`user_id = 1`。普通管理员角色不自动绕过资源范围。
- 考试管理列表、导出、详情、名单、题目配置、发布、修改、删除和理论批改均受保护。
- 新考试负责人取自登录用户 ID；请求不能指定或修改负责人，创建和修改的审计身份由后端确定。
- 列表在 SQL 层过滤，先过滤再分页；学生考试仍按准入名单和本人会话授权。
- 这是权限底座的一部分，不代表 PRD 的题库范围、裁判任务绑定、复核角色等全部完成。

## 部署顺序

1. 选择无考试进行的维护窗口，记录当前应用版本，备份业务库并验证备份可用。
2. 在目标业务库执行 `exam_ownership.sql`，先迁移数据库，再发布新后端。该脚本支持重复执行。
3. 确认 `exam_info.owner_user_id` 列及 `idx_exam_owner` 索引存在。
4. 启动新后端，完成下方验收。开发阶段未执行迁移；本机后续维护结果见下方部署记录。

旧代码没有可信的负责人记录，因此旧考试的负责人保持 NULL，只对内置管理员开放。
不得根据历史 `create_by` 自动授予权限，也不能批量将全部旧考试赋给某个教师。
如需移交历史考试，管理员须先逐场核实负责人及账号有效性；由维护人员在维护窗口内进行受控数据库变更，
只更新已核实且负责人仍为空的记录，保留原值、操作者、时间、依据和变更记录。本轮未提供负责人转交界面。

## 验收

1. 教师 A 创建考试；即使提交其他人的 `ownerUserId` 或伪造 `createBy`，实际负责人仍是 A。
2. 教师 B 在管理、导出及批改列表中看不到 A 的考试。
3. B 直接请求 A 的考试详情、名单、题目分值、答卷、发布或批改接口，应返回权限错误，且无数据写入。
4. A 具有对应接口权限时可管理和批改自己的考试；发布后的不可修改限制仍生效。
5. 内置管理员具有全场次资源访问权；历史无负责人考试不对普通教师开放。
6. 批量删除中混入无权访问的考试，应整体失败，不删除任何考试及关联。
7. 学生仍可进入名单内的已发布考试并保存、交卷；不能越权访问其他人的答卷。
