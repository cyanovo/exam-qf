## 独立评测服务

在隔离 Linux 主机或 VM 上按 Judge0 官方部署说明安装经核查的版本。
不与业务数据库、Redis、文件存储同机；不要挂载业务目录、宿主 Docker socket 或凭据。
采用访问白名单，只允许业务后端访问评测 API。学生网络不能直连评测 API。
阻止评测工作负载访问互联网、内网业务服务、宿主服务和云元数据地址。
应用的 `enable_network=false` 只是纵深防御，不能代替主机防火墙和隔离验收。
不要为了启动成功删除官方沙箱需要的隔离配置，或在业务主机上启用特权容器。

后端环境变量：

```text
EXAM_JUDGE_ENABLED=true
EXAM_JUDGE_URL=http://<isolated-runner-host>:2358
EXAM_JUDGE_TOKEN=<private-secret>
EXAM_JUDGE_PYTHON_LANGUAGE_ID=<verified-id>
```

默认禁用。使用私密配置提供令牌，不写入仓库、前端或公开日志。
前端必须由 HTTPS 或 localhost 提供，代码摘要需要浏览器 Web Crypto。
适配器固定 CPU 2 秒、墙钟 5 秒、内存 128 MiB、进程线程数 16、文件 64 KB，
关闭网络，不提供自定义编译命令、额外文件或回调地址。

比较规则：

- EXACT 仅统一 CRLF 为 LF，不忽略空白。
- NUMERIC 使用绝对误差，容差范围 0 到 1，限制数字长度和指数规模。
- JSON 为严格结构比较，不接受尾随内容；数字节点类型不同可能判为不同。

## 维护窗口上线顺序

1. 确认没有正在考试的会话，安排维护窗口；不要直接中断现有考试。
2. 备份数据库、运行 JAR、前端文件和配置，在独立库验证备份可以恢复。
3. 确认旧基础迁移（包括考试快照、会话、成绩修订、权限归属）已存在。
4. 在生产执行 `exam_results.sql`、`exam_coding.sql`、`exam_result_permissions.sql`。
5. 管理员为专门的复核角色授予复核权限，考试负责人绑定对应复核员。
   权限 SQL 不会将复核权自动授予全部教师。
6. 部署独立沙箱并完成下列验收，再启用 `EXAM_JUDGE_ENABLED`。
7. 发布同版本后端和前端，检查启动日志、自动判分任务和权限路由。
8. 用专用测试考试验证完整流程，不能用正在考试的学生账号或数据验证。

回退时先停止新提交并保留代码任务、快照和审计记录；不要删除新表。
评估是否已有新版本成绩发布后，再决定恢复旧程序或从备份恢复数据。

## 必须补做的上线验收

- 真实执行：正确/错误答案、语法错误、异常、死循环、超内存、大输出、多进程。
- 隔离：文件越界、网络外连、内网探测、宿主及元数据访问、已知逃逸回归。
- 故障：断网、评测服务重启、后端重启、超时、重复提交、截止边界、租约过期。
- 权限：学生不能读取他人提交或隐藏测试；非绑定复核员不能批准或发布。
- 流程：正式提交、交卷、自动评分、独立复核、发布、学生查分、更正和重新发布。
- 性能：按 PRD 负载进行 50–200 人验收，记录排队时延、失败率和资源用量。
- 全局队列容量和跨考试用户限流目前不是严格串行计数，不能声称已通过峰值并发限流验收。
