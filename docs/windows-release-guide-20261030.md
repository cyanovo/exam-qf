# 一键启动与简单使用说明

当前交付版本：`20261030-exam-user-v3`。审核与部署检查结果见 `release-verification-20261030.md`。

## 先启动

本次是现有项目的 Windows 升级版，不是免安装的全新电脑发行包。
当前电脑已配置 Java、Node、MySQL、Redis 与 Python 评测容器。
启动前保持 MySQL 服务、Docker Desktop 正常运行。运行发布版不需要 Maven 或前端开发服务器。

1. 打开 `D:\work\cyan-exam-main`。
2. 首次部署或升级：双击 `deploy.cmd`。脚本先检查依赖、备份，再迁移数据库并启动服务。
3. 日常启动：双击 `start.cmd`。已经启动时不会重复启动。
4. 浏览器访问 `http://127.0.0.1:5190`，不要再打开旧的 5177/5178 页面验证本版功能。
5. 停止本版：双击 `stop.cmd`，不会关闭共享 MySQL、Redis、Docker，也不会结束其他会话的进程。

CMD 和 PowerShell 都可以执行上述 `.cmd` 文件。PowerShell 中在项目目录输入 `.\start.cmd`。
不要复制命令行前面的 `PS C:\Users\cyan>` 或 `C:\Users\cyan>`。

版本文件放在 `releases`，包含后端、构建后的网页、数据库迁移与 SHA256 清单。
自动部署按发布清单的构建时间选择最新版本，不按目录名猜测。
首次无本地配置时会询问数据库密码，生成 `deploy/windows/config.local.json`。
当前电脑的配置已准备好；换电脑需修改工具路径、数据库、文件目录和沙箱配置，迁移现有数据库及附件。
脚本不会下载运行环境、清空数据库、重设账号密码，也不会自动初始化一套空白业务库。

## 用户与考试分组

用户管理使用“登录账号、姓名、所属分组”区分登录信息与人员信息。
左侧为考试分组：考试中心下设考务组织、考生分组。
进入“系统管理 → 分组管理”可将考生分组改成实际班级或考试批次名称。
考务岗位用于人员登记，访问权限仍由角色决定，不会因为修改岗位名称自动增加权限。
本次升级只替换原始示例公司及岗位名称，保留组织编号、用户归属和授权关系，自定义名称不会被覆盖。

## 题库审核

进入“题库管理”，新增或导入的题目先进入“草稿”。

| 状态 | 操作与结果 |
|---|---|
| 草稿 | 命题人员修改后送审 |
| 待审核 | 审核员“查看”完整内容，选择通过或退回；退回需写原因 |
| 待审核 | 命题人员可以撤回；不能直接修改待审核内容 |
| 已发布 | 可以用于新考试发布、从题库添加机器人任务 |
| 已发布 | 修改后重新进入草稿，必须再次审核；也可以停用 |
| 停用 | 不能用于新考试，转草稿后可以修改、重新送审 |

“记录”显示操作、版本、操作人、意见和时间。每次创建、编辑和状态变化在数据库保留内容快照。
并发编辑时以版本校验防止互相覆盖；提示内容已变化时，刷新再操作。
旧题目升级时：原启用题目兼容为“已发布”，原停用题目为“停用”；没有伪造历史审核记录。
已经发布考试中的题目快照不因题库后续修改、停用而变化。

命题权限与审核权限分开，命题教师不会自动取得审核通过权限。
管理员可在角色管理授予“题目审核”。本次迁移给现有业务审核员增加题目审核和查看权限，
不会重建角色或把其他已撤销权限批量补回。

## 设备与工位

进入“系统管理 → 设备与工位”。管理员默认可维护；其他人员需管理员授权。

1. 在“考场工位”新增编号、位置、联系人及备注。
2. 在“设备台账”新增设备编号、型号、资产状态，选择已有工位。
3. 设备可设为可用、维修中、已报废。报废时解除工位绑定。
4. 一个工位可登记多台设备。删除工位前，先解除关联设备的绑定。
5. 搜索和状态筛选后点击“导出”，导出当前筛选结果的全部行，不仅是当前页，格式为 Excel 可打开的 UTF-8 CSV。

台账只管理设备信息，不连接、不驱动机器人。学生仍然在线写代码提交，现场裁判按实际运行步骤评分。

## 备份、恢复与回滚

在项目目录的 PowerShell 中：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\Manage.ps1 -Action Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\Manage.ps1 -Action Backup
```

备份位于 `.runtime-release/backups/日期时间`，包括数据库、上传文件、私有成果证据目录、本地配置及沙箱令牌。
备份包含敏感数据，仅当前 Windows 用户和 SYSTEM 有访问权限；不要直接分享备份。
SHA256 校验用于发现意外修改，不等同于可信发布者数字签名。
迁移失败不会记为成功，也不会继续启动新版；已经完成的加列可能保留，修复后可重试。

双击 `rollback.cmd` 回到上一个受管发布版本。第一次部署没有上一版本，会明确提示。
回滚切换程序，不删除新增表或字段，不把考试数据退回旧时刻。只支持本版兼容的增量数据库结构。
需要恢复数据时使用下面命令，目标必须是不存在的 `cyan_restore_` 开头数据库：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\Manage.ps1 -Action Restore -BackupPath "D:\work\cyan-exam-main\.runtime-release\backups\实际备份目录" -RestoreDatabase cyan_restore_manual
```

恢复前核验备份文件摘要。恢复不覆盖当前数据库，附件恢复到 `.runtime-release/recovery/目标数据库`。
核对用户、试卷、答卷、分数与证据后，停止服务，再调整本地配置的数据库与 Profile 指向恢复目录。
设置 Profile 为恢复目录下的 `uploads`，脚本会将私有证据放到相邻的 `uploads-exam-private`；不要只切数据库而遗漏附件。

配置每日 02:00 自动备份：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\Register-Backup.ps1 -At 02:00
```

此命令需主动执行，本次不擅自安装计划任务。任务在当前 Windows 用户登录期间执行，错过后补跑；
无人值守服务器应由管理员另配服务账号。备份暂不自动删除，保留期限由学校决定，定期复制到异机。
在无考试、无其他程序写库的维护窗口升级、备份和恢复；脚本不能暂停另一个独立启动的旧服务。

## 遇到异常

| 现象 | 检查 |
|---|---|
| 端口被占用 | 脚本不会杀占用者；修改本地配置 ApiPort/WebPort，或手动关闭确认不再使用的旧服务 |
| 数据库连接失败 | 检查 MySQL 服务、库名、账号密码；脚本不会创建或重置 MySQL root |
| Python 沙箱不可用 | 先打开 Docker Desktop，确认配置中的两个容器存在；初始化参考 `deploy/go-judge` |
| 启动后页面卡住 | 查看 `.runtime-release/logs`，刷新浏览器，确认访问 5190 而非旧版本 |
| 提示字段或迁移缺失 | 执行 `deploy.cmd`；不要绕过迁移直接双击 JAR |
| 审核或台账菜单不可见 | 使用管理员账号检查角色权限，重新登录；不要通过更换用户密码解决权限问题 |
| 密码未知 | 由管理员在用户管理重置；系统只保存哈希，不能解密原密码 |

账号清单见 `docs/private/current-accounts.md`。该文件不进入 Git 和发布目录。
本版默认仅本机访问；学校局域网正式部署还需要 HTTPS、网络边界、最小权限数据库账号、容量与安全验收。
本次没有把 Windows 本机启动版表述为 PRD 中 Linux/Docker/Nginx 正式部署拓扑的完整交付。
