# 机器人实操编程流程修正

本说明以用户最新确认的业务流程为准，替代此前将现场任务描述为答辩、演示或强制成果上传的说明。

## 正确流程

1. 教师添加选择、判断、填空、Python 基础编程题。机器人题可在考试列表“选择题目”中按“机器人实操编程”筛选添加，也可在“考试编排 > 章节与题目顺序 > 新增机器人实操编程题”添加。配置观察时长、运行步骤及各步骤满分，不指定评委。
2. 教师分配学生、设置章节顺序和考试时间，统一发布。
3. 学生在同一份试卷内作答。机器人题也使用在线代码编辑器，草稿自动保存，点击“提交代码”留存正式版本，无需进入另一套现场任务页面或上传文件。
4. 现场按提交代码运行机器人。系统不直接连接或控制机器人，也不会将机器人代码交给 Python 沙箱自动判分。
5. 学生正式提交后，所有具有实操评分权限的评委均可在“机器人实操评分”选择考试和已提交的考生，查看正式代码，依据实际运行情况逐步给分、提交评分。首次保存评分的评委成为该份评分的实际评分人；其他评委可以查看，但不能覆盖。学生端没有侧边栏和实操评分入口。
6. 原有成绩汇总、复核、发布与撤回审批流程保持不变。Python 基础编程题仍走原自动评测，客观题仍走原判分流程。

## 数据与边界

- 每个草稿按实操题、考生隔离；每次正式提交保存独立代码版本、服务端哈希和接收时间。
- 重复请求使用同一提交标识返回原记录，不重复产生版本。
- 非本场考生、其他考生、无评分权限的账号不能越权读取或修改代码。评委只能访问已发布的实操任务。
- 交卷、个人作答截止、场次截止、人工终止后不能新提交。
- 正常评分请求必须携带当前正式提交编号；版本过时必须重新打开代码后评分。考试结束或人工终止后，评委可对未正式提交代码的考生确认“未提交，记0分”，只允许所有步骤记零，不伪造代码提交。
- 裁判首次保存评分后，考生不能再更换正式代码。已提交评分修改仍需原撤回审批。
- 同一考生同一任务只有一份评分，以实际评分人而非任务绑定人判断修改和撤回权限。服务端事务锁、版本检查和评分人检查共同阻止并发覆盖；撤回须由原评分人发起，管理员不能审批自己的评分撤回。
- 机器人代码有未正式提交的修改时，手动交卷会提醒先提交。到时自动交卷不等待草稿补交，以服务器最后正式提交为准。
- 既有未关联代码的历史评分不自动伪造提交，不删除成绩；查询仍保留，重新评分必须先有正式代码。

## 白卷处理

- 只需清理空考试时，直接在考试列表删除，无需先评分或复核。仅允许已结束或人工终止且全员无实际答案、代码、人工评分、成绩版本、异常和文件材料的考试；系统自动生成的空答案及零分记录不再阻止删除。
- 需要保留成绩时，在实操评分页对未提交代码的学生确认记零，再按原流程锁定、复核、发布。人工确认的零分也是正式评分记录，不能再按空考试直接删除。
- 删除前检查整场考试；任一学生有受保护记录则拒绝删除。批量删除先全部检查，再统一执行，失败不会只删除一部分。
